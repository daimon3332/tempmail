## 四、需要你决策/确认的点

1. **范围确认**：以上"原版全部 + 参考补充 + 自研建议"是否全部纳入？有没有想砍的？是否要我把"自研建议"再分级（P0 必做 / P1 建议 / P2 可选）？
2. **实时推送**：用 SSE（更省、真·实时）还是保持轮询（最简单）？我建议 SSE。
3. **审计日志 & API Key**：这两个涉及安全边界。仅本地自己用，可简化为"操作日志"和"站点头"。要加吗？
4. **Worker 配置页**：我们无 Worker，改为展示 `.env` 运行配置，等价值是否可接受？
5. **SMTP 中继 / S3 / AI 端点**：这些配置项对应的外部服务你没提供，前端做成"可配置 UI + 未配置时置灰提示"，还是直接隐藏那些 tab？我建议：显示但置灰并提示"需在 .env/UI 配置"。

## 六、最终决策（用户已确认 2026-09-04）

- **全部纳入**：原版全部 + 参考补充 + 自研建议（我会在金 P0 必做 / P1 建议 / P2 可选）。
- **实时推送用 SSE**（真·实时，替代轮询）。
- **操作日志**（简化审计：记录管理员关键写操作，时间/IP/操作/结果）。
- **独立"配置页"**：集中管理可热更新配置（AI 端点、站点/管理员密码开关、API Key、站点信息、地址创建、功能开关），点保存**立即生效**（无需重启）。域名列表因涉及 SMTP/MX，改后重启生效（文档注明）。
- **API 用法文档单页**：一个 HTML 页，介绍项目各类 API 示例与用法（参考 `temp-mail-docs.awsl.uk/zh/guide/feature/agent-email` 风格），面向 Agent/开发者。
- **S3 与 SMTP 中继不做**：前端隐藏对应 tab；后端 S3/SMTP_CONFIG 代码保留但配置页不展示、不引导。发信仍走直连 MX / SMTP。
