添加 Cloudflare 邮箱域名

适用于已托管在 Cloudflare 的域名。邮件由 Cloudflare Worker 转发到你的 Tempmail 服务器，无需部署原版邮箱、网站代理或数据库。

1. 部署收信 Worker

  1. 在该域名所属的 Cloudflare 账号中打开“Workers 和 Pages”，创建 Worker，命名为 tempmail-ingest。同账号已有这个 Worker 时可以复用。
  2. 点击“编辑代码”，用下方代码替换默认代码，部署。
  3. 在 Worker 的“设置 → 变量和机密”中添加以下两项，保存并部署。
ORIGIN_URL（文本）
Tempmail 网站的 HTTPS 地址，例如 https://mail.example.com。不要追加 /external/ingest。
INGEST_TOKEN（Secret / 机密）
与服务器“系统设置 → 环境变量与高级配置 → Worker 收信令牌”的值完全一致。已有令牌直接复用；首次设置或修改服务器令牌后，保存并在服务器运行 docker compose up -d --force-recreate。不要填写用户密码或 API Key。

2. 设置全收（Catch-all）

  1. 打开该域名的“电子邮件路由 / Email Routing”。首次启用时，按 Cloudflare 提示添加所需 DNS 记录；如果域名正在使用其他邮箱服务，不要覆盖它的 MX，改用独立子域。
  2. 在“路由规则”找到全收，编辑为“发送到 Worker → tempmail-ingest”，保存并启用。

不需要为每个邮箱单独建规则。已有单独规则会优先匹配，请确认它们也指向正确的 Worker。使用固定子域时，先在 Email Routing 的“设置 → 子域”启用该子域。

3. 在 Tempmail 添加后缀

  1. 打开“系统设置 → 域名与新建邮箱”，输入后缀，例如 example.com，点击“添加域名”，再点击页面顶部“保存”。
  2. 先关闭“允许随机子域”：根域的全收规则不会自动接收任意随机子域的邮件。
  3. 新建一个该后缀的邮箱，用外部邮箱发一封邮件，确认在网站中收到且正文、附件正常。仅添加后缀无需重启服务器。

收不到邮件时，先查看 Cloudflare Email Routing 和 Worker 日志。401 通常表示收信令牌不匹配；未知邮箱被拒收时，先在网站创建该邮箱再发信。
